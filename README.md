# День 30. Локальная LLM как приватный сервис

Домашний компьютер с GTX 1050 Ti (4 ГБ) превращён в приватный AI-сервис: HTTP API и веб-чат поверх локальной
`qwen2.5:3b` в Ollama. Модель, чаты и журнал остаются на этом компьютере; в домашнюю сеть смотрит только шлюз
с API-ключами и лимитами.

Стек: Python 3 (только стандартная библиотека: `http.server`, `sqlite3`, `threading`, `urllib`) + vanilla HTML/CSS/JS.

```
телефон / ноутбук / curl ──HTTP, ключ──►  шлюз :5300 (0.0.0.0)  ──►  Ollama 127.0.0.1:11434  ──►  qwen2.5:3b на GPU
                                          ├ API-ключи (в файле только SHA-256)
                                          ├ rate limit и параллельность на ключ
                                          ├ очередь к видеокарте (1 генерация, до 6 ждут)
                                          ├ max context: обрезка истории, 413 на огромное сообщение
                                          └ SQLite: чаты каждого ключа, журнал запросов без текста
```

Ollama по-прежнему слушает только `127.0.0.1`. Без ключа из сети доступен лишь `/health`.

## Запуск

```bat
run.bat
```

При первом запуске создаётся ключ администратора: он выводится в консоль и сохраняется в `data/first-key.txt`.
Консоль показывает адреса — `http://127.0.0.1:5300/` и адреса компьютера в сети, например `http://192.168.100.189:5300/`.
Если консоли нет (запуск фоновой задачей), сервис работает молча: вывод в консоль не роняет запросы.

Ключи для других устройств и людей:

```bat
python app\keys.py add phone --rpm 10 --concurrency 1
python app\keys.py list
python app\keys.py remove phone
```

Ключ показывается один раз; на сервере хранится только его хэш.

### Доступ из домашней сети

Сеть «Ethernet 3» в Windows помечена как **общедоступная**, поэтому брандмауэр не пропускает входящие подключения
с других устройств. Разрешить порт 5300 нужно один раз, в PowerShell от имени администратора:

```powershell
New-NetFirewallRule -DisplayName "Private LLM 5300" -Direction Inbound -Protocol TCP -LocalPort 5300 -Action Allow -Profile Private,Public -RemoteAddress LocalSubnet
```

`-RemoteAddress LocalSubnet` пускает только устройства из своей подсети, а не весь интернет. На роутере порт
наружу не пробрасывается: сервис домашний. Для доступа извне лучше VPN до дома (WireGuard или Tailscale),
а не открытый порт.

## HTTP API

Ключ передаётся в заголовке `Authorization: Bearer <ключ>` (или `X-API-Key`).

| метод | путь | что делает |
|---|---|---|
| GET | `/health` | без ключа: жив ли сервис, загружена ли модель, очередь |
| GET | `/api/me` | имя ключа, лимиты, сколько запросов осталось в текущей минуте |
| GET | `/api/models` | модели сервиса (`qwen2.5:3b` по умолчанию, `llama3.2:3b`) |
| POST | `/api/chat` | `{message, chat_id?, model?, temperature?, max_tokens?, stream?}` → `{chat_id, reply, usage}` |
| GET | `/api/chats` · `/api/chats/<id>` | чаты этого ключа и история |
| DELETE | `/api/chats/<id>` | удалить чат |
| GET | `/api/admin/stats` | только для ключа администратора: очередь, отказы, клиенты и журнал за час |

История диалога хранится на сервере: чтобы продолжить разговор, передайте `chat_id` из прошлого ответа.
С `"stream": true` ответ приходит потоком NDJSON: `{"type":"meta"}` → `{"type":"token","text":…}`… → `{"type":"done","usage":…}`.
Если клиент рвёт соединение, генерация в Ollama сразу останавливается.

```bash
curl -s http://192.168.100.189:5300/api/chat -H "Authorization: Bearer lsk_…" -H "Content-Type: application/json" -d "{\"message\": \"Привет! Кто ты?\"}"
```

В каждом ответе есть заголовки `X-RateLimit-Limit`, `X-RateLimit-Remaining`, `X-RateLimit-Reset`.
Ошибки имеют один формат: `{"error": {"code", "message", "retry_after"}}`, а для 429/503 ещё и заголовок `Retry-After`.

## Ограничения ([`config.json`](config.json))

| ограничение | значение | ответ при превышении |
|---|---|---|
| запросов к модели на ключ | 10 в минуту (скользящее окно; у ключа можно задать своё) | 429 `rate_limited` + `Retry-After` |
| одновременных генераций на ключ | 2 | 429 `too_many_parallel` |
| генераций на видеокарте | 1, остальные ждут в очереди | — |
| очередь | до 6 ожидающих, ожидание до 120 с | 503 `queue_full` / `queue_timeout` + `Retry-After` |
| окно контекста модели | 3072 токена (`num_ctx`, настройка Дня 29) | длинная история обрезается со старых сообщений |
| одно сообщение | до 8000 символов и не больше окна минус ответ | 413 `message_too_long` / `context_too_large` |
| ответ | до 512 токенов (`max_tokens`) | 400 `max_tokens_out_of_range` |
| тело запроса | до 64 КБ | 413 `body_too_large` |
| неверные ключи с одного IP | 20 в минуту | 429 `auth_blocked` (верный ключ с того же IP проходит) |

Токены оцениваются с запасом (2,5 символа на токен для кириллицы, 3,5 — для остального): у Ollama нет HTTP-токенизатора.
Фактический размер промпта берётся из ответа Ollama (`prompt_eval_count`) и показывается в `usage.prompt_tokens`.

## Проверка: [`tools/check.py`](tools/check.py)

```bat
python tools\check.py --url http://192.168.100.189:5300 --clients 10
```

Скрипт обращается к сервису по адресу в сети, создаёт временные ключи для проверки лимитов, удаляет их в конце
и пишет отчёт в `data/check-report.json`. Проверяет:

- **доступ по сети** — `/health` по адресу `192.168.100.189:5300`, ключи (401 без ключа и с чужим ключом);
- **чат** — ответ модели, история на сервере (кодовое слово из первого сообщения), стриминг NDJSON;
- **стабильность** — N клиентов со своими ключами одновременно, по 2 запроса. Сверх ёмкости очереди клиент
  получает 503 с `Retry-After` и повторяет запрос, в итоге должны быть обслужены все и без других ошибок;
- **rate limit** — 5 запросов при лимите 3 в минуту: `200, 200, 200, 429, 429` с `Retry-After`;
  два параллельных запроса при лимите 1 дают 429 `too_many_parallel`;
- **max context** — 413 на слишком длинное сообщение и на не влезающее в окно; 400 на `max_tokens` сверх лимита
  и на неизвестную модель; 413 на тело больше 64 КБ; обрезка длинной истории — промпт не выходит за 3072 токена;
- **перебор ключей** — после 20 неверных ключей с IP — 429; верный ключ с того же IP по-прежнему работает.

### Результаты

| проверка | результат |
|---|---|
| доступ по сети | `/health` по `http://192.168.100.189:5300` за 0,04 с |
| ключи | без ключа и с чужим — 401, с ключом — 200 и заголовки `X-RateLimit-*` |
| чат | ответ за 0,5 с (модель в памяти), история: «БИРЮЗА» вспомнила через сообщение, чат сохранён (4 сообщения) |
| стриминг | первый токен через 0,09 с |
| 6 клиентов × 2 запроса | 12/12 ответов, медиана 5,1 с, максимум ожидания в очереди 4,5 с, всё за 11 с |
| 10 клиентов × 2 запроса | 20/20 ответов, других ошибок 0; 3 раза клиент получил 503 `queue_full` (1 в работе + 6 в очереди — больше не принимается) и повторил запрос после `Retry-After`; медиана 4,1 с, максимум 7,1 с, ожидание в очереди до 6,1 с |
| rate limit 3/мин | `200, 200, 200, 429, 429`, `Retry-After: 60`, `X-RateLimit-Remaining: 2 → 1 → 0` |
| параллельность 1 | `[429 too_many_parallel, 200]` |
| max context | 413 `message_too_long`, 413 `context_too_large` (~3105 токенов при лимите 2560), 400, 413, 400 |
| длинная история | отброшено старых сообщений по шагам `[0, 0, 0, 2, 4, 6]`, промпт по данным Ollama `648 → 1237 → 1826` и дальше не растёт |
| перебор ключей | 401, затем 429 `auth_blocked` (порог — 20 неверных ключей с IP в минуту, считая проверку авторизации); верный ключ с того же IP — 200 |

Итого: **17/17 проверок** (`python tools\check.py --url http://192.168.100.189:5300 --clients 10`).

## Веб-чат

`http://<адрес>:5300/` — вход по ключу (ключ хранится в `localStorage` браузера и уходит только на этот сервер).
Список чатов этого ключа, ответ стримингом с кнопкой «стоп», выбор модели, `temperature` и `max tokens`,
под ответом — токены, скорость, время, ожидание в очереди и отметка, если из контекста убраны старые сообщения.
Для ключа администратора есть панель **«сервис»**: очередь, обслужено и отказы по типам, модель в памяти,
ключи и их расход, ответы за час по статусам, клиенты по IP и последние запросы (без текста сообщений).
